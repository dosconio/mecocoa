# 内存映射

## 普通文件映射权限

`mmap` 使用已打开文件描述符授予的访问权限。R、W、X 分别表示读、写、执行。下表列出 R、W 的权限上限，X 另受挂载执行策略约束。

| 文件打开方式、挂载状态 | `MAP_PRIVATE` 权限上限 | `MAP_SHARED` 权限上限 |
| --- | --- | --- |
| `O_RDONLY` | R、W，允许私有 COW | R |
| `O_RDWR`，可写挂载 | R、W | R、W |
| 只读挂载上的可读 fd | R、W，允许私有 COW | R |
| `O_WRONLY` | 拒绝文件映射，包括初始 `PROT_NONE` | 拒绝文件映射 |
| 非普通文件 | 此普通文件映射入口拒绝 | 此普通文件映射入口拒绝 |

`MAP_PRIVATE` 的写入修改进程自己的副本，通过写时复制（COW）实现。`MAP_SHARED` 的写入修改共享文件内容，需要可读写文件描述符和可写挂载。root 同样受 fd 打开方式和挂载限制约束。权限上限表示授权范围，映射仍可能因参数、内存或文件状态而失败。

文件映射成功后，即使关闭原 fd，映射仍持有文件引用。后续 `mprotect` 使用建立映射时保存的权限上限。fork、区域拆分和部分解除映射会保留这一上限。将当前权限降为 `PROT_NONE` 后，可以恢复上限内的权限。

例如，使用 `O_RDONLY`，以 `MAP_SHARED` 和 `PROT_READ` 建立映射后，不能用 `mprotect` 增加 `PROT_WRITE`。同一个 fd 以 `MAP_PRIVATE` 和 `PROT_READ` 建立的映射则可以在之后增加 `PROT_WRITE`，写入结果保留在私有副本中。

## 执行映射

可读 fd 在允许执行的挂载上可以申请 `PROT_EXEC`，也可以在权限上限内通过 `mprotect` 增加执行权限。普通共享库可使用 `0644` 文件权限。主 ELF 和 `PT_INTERP` 解释器启动时另外检查文件执行位。

内核挂载参数 `no_execute` 默认关闭。启用后，禁止从该挂载启动主 ELF 或解释器，也禁止文件映射取得 X 权限，包括 UID 0。挂载策略随文件引用保留，unlink 或卸载后也继续有效。该选项限制文件执行，不限制进程将可读文件内容复制到匿名内存。

当前 x86-32 页表路径不能使用 NX 区分可读与可执行页，因此禁止执行挂载上的文件映射只接受初始 `PROT_NONE`，并拒绝后续改为可访问。其他 MMU 平台按已有页表和硬件能力执行保护，缺少所需能力时申请会失败。

## 修改映射保护

`mprotect` 在修改前检查整个地址区间，要求区间连续覆盖有效 VMA，且每段都允许请求的权限。覆盖权限上限不同的多个区域时，其中任意一段拒绝就会使整个申请失败。当前普通 `mprotect` 不接受设备 VMA。

映射支持 `PROT_NONE`，或包含 `PROT_READ` 的 R、RW、RX、RWX 组合。`MAP_FIXED` 当前用于替换已有的匿名 `PROT_NONE` 预留区，新文件映射使用自身的权限上限。

## noMMU

noMMU 当前通过旧式匿名 RW 分配请求为用户堆扩容。文件映射、结构体形式的 MMAP 请求和 `mprotect` 返回失败。失败请求不会推进用户堆顶。
